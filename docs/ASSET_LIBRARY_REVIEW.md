# 图库资产生命周期、PNG 元数据与 Vibe 持久化

更新日期：2026-10-13。范围：PC 工作区、图库索引、受管图像文件、PNG 参数导入和 Vibe 库/缓存。实现、自动化回归及 Web/Windows 构建通过；本批内置浏览器交互验收未完成。

## 当前行为

| 操作 | 当前行为与边界 |
| --- | --- |
| 导入图片 | 图片先通过格式、大小和内容校验，再写入内容寻址的受管存储并加入图库索引。支持 PNG、JPEG 和 WebP；当前参数解析范围是 PNG。 |
| PNG 参数回填 | 解析 PNG 文本参数和受支持的隐写参数后，用户可选择回填字段。未选字段及图片中没有的字段保留草稿当前值；解析不修改源图。 |
| 移除图库记录 / 清空图库 | 只保存索引变化并清除无效选择，不删除图像字节。文件仍可能由草稿、任务、编辑层、父子结果或 Vibe 库使用。 |
| 只读资产审计 | 递归遍历序列化工作区中的对象、列表和值，仅识别完整且有效的受管资产引用；通过 store 读取引用文件以验证内容哈希和格式。分别报告已引用、缺失、损坏和未引用资产，不修改数据。缺失、损坏与未引用分类可能重叠。 |
| 恢复图片 | 用户显式选择后，将仍可读取的未登记文件加入图库，并尝试解析 PNG 参数。它不能恢复图片本身不存在的草稿或历史字段。 |
| 清理文件 | 用户显式确认后，只考虑本次批准、仍在 store 清单中且重新扫描工作区后仍未被引用的资产。先提交工作区修订，再逐项复核引用；失败的索引保存会阻止文件删除。应用没有自动垃圾回收。 |
| Vibe 库和缓存 | 命名条目与有界编码缓存保存在工作区中。兼容性按模型、协议/服务端点和 information extracted 范围判断；生成 strength 可独立调整。失败编码不进入缓存。已保存条目的源图片引用也受资产扫描保护。 |

## 存储和删除安全边界

`ImageAssetStore` 继续只负责保存、读取和关闭；独立可选接口 `ImageAssetMaintenance` 提供列出受管引用和幂等删除，避免要求所有现有 store 替身都实现维护能力。IO 与 Web store 各自实现该接口，文件操作仍通过 store 处理。

IO store 只接受规范的 SHA-256 资产引用，不把用户传入字符串当成任意路径。资产枚举限定在受管 `sha256` 命名空间，只列普通文件；维护时约束目录类型并检查解析后的目录位置。符号链接或路径异常不会被当作可删除资产。读取还会重新验证文件字节与引用哈希；删除不存在的受管引用为幂等操作。审计若遇到普通访问错误会中止并返回错误，不把访问失败误判为“未引用”。

递归收集器只接受精确有效引用。损坏、不完整或任意路径字符串不会因为出现在快照里而授权清理。引用扫描跨越嵌套参数、会话、候选、父子关系和库条目，因此新增快照字段无需用字段名白名单决定资产是否受保护。

维护期间工作区会阻止生成及导入/图片编辑类操作。图库删除和文件清理是分开的生命周期步骤：索引变更先持久化；只有随后由用户明确发起的清理才会删除文件。清理过程中发现新引用时跳过该文件。此设计保留文件恢复余地，也避免空图库被误解为所有图片都无主。

revision 检查和本进程互斥不等于数据库与文件删除的跨进程原子事务；本批未验证多个应用实例同时维护同一工作区。大图库目前采用每次展开 60 条的呈现限制，仍在内存中搜索；没有完成大规模图库性能验收。清除索引后，恢复只覆盖未被任何工作区字段引用的有效受管文件，不能重建图片中未记录的完整历史。

PNG 支持 `tEXt/iTXt/zTXt`、alpha 隐写及受限 RGB 隐写。解析具有 CRC、结构、大小和解压上限检查；RGB 隐写只对解码后完全不透明图片尝试，颜色转换仍可能影响低位信息。缺失 Vibe 强度/信息提取数组时整组跳过并警告，不编造原始参数。格式来源与限制见 [来源说明](evidence/image-metadata-source-note.md) 和 [PNG 文本块规范](https://www.w3.org/TR/png-3/#11textinfo)。

Vibe 编码缓存按源资产、SHA-256、模型、协议、端点和信息提取值区分，生成强度不参与编码键。只有源图缺失的外部编码需要在界面明确确认适用范围；未确认编码不能直接生成。命名、搜索、重命名、删除、复用与缓存清理均有入口。编码支持用户取消，关闭工作区时也会中止本地等待；不会自动重试。

## 与手机端的关系

先前只读审计的手机端历史清空语义是删除历史索引而保留本地/系统相册中的图片，PC 的“清空图库”采用相同的索引优先语义。既有全量审计快照 HEAD 为 `375a41844be53136f7d2350c2d6560f221a8c5a5`；当前手机端 HEAD 为 `01e85981a52b5d45d3cb6d1ee03a8604fe53d9ab`。本批只参考相关元数据、图库和 Vibe 模块，没有在新 HEAD 上重新完成全部功能调查；[MOBILE_PARITY.md](MOBILE_PARITY.md) 的历史证据范围保持原标注。PC 代码独立实现，未复制许可不明确的手机源码，也未复制 Local Web 的 AGPL 实现。
