## 证据口径

矩阵的完整通过需要同时满足各行定义的前置、触发、副作用计数、持久证据和层级。下表中的“有覆盖”只表示具体断言已经存在；“部分”表示测试只覆盖分支或较低验证层，不能代替整行。验证使用合成资料、本地 SQL、fake provider 和本机 HTTP fixture；没有发送真实模型或收费图片请求。

验证层缩写：SC=合同/静态验证，PI=Pi 回合/工具装载，H=真实产品 Host，D=真实 SQLite 文件与持久读回，Q=Worker/队列，UI=React renderer，N=隔离的 Windows/Electron 原生运行。层级与冻结矩阵中的要求一致。

最终批量验证记录见 [validation-summary.json](evidence/agent-r4/2026-10-18/validation-summary.json)、[vitest-final.json](evidence/agent-r4/2026-10-18/vitest-final.json) 和 [build-manifest.json](evidence/agent-r4/2026-10-18/build-manifest.json)：Vitest 480 个测试文件、4338 项（4336 通过、0 失败、2 跳过）；`npm run typecheck`、`npm run build` 和 Windows x64 `electron-builder --dir --win --x64 ... --publish never` 均 exit 0。构建仍有大 chunk 提示；打包证据是未安装的 x64 目录，不是安装包或发布。两个 skip 是本地 Real-CUGAN CLI 合成图测试与 Vibe 混合 bundle fixture。此前 pass4 的 4260 项、12 失败报告是历史快照，已被上述最终全量结果取代。

隔离原生证据见 [native-final-main.json](evidence/agent-r4/2026-10-18/native-final-main.json)、[native-renderer-evidence.json](evidence/agent-r4/2026-10-18/native-renderer-evidence.json)、[native-ui-interactions.json](evidence/agent-r4/2026-10-18/native-ui-interactions.json) 和 [native-unknown-gate-ui.json](evidence/agent-r4/2026-10-18/native-unknown-gate-ui.json)。运行的是实际 Windows Electron main、preload/IPC 与 renderer，使用隔离 synthetic profile；画廊/方案/预览/队列记录均为合成数据。UI smoke 无运行时错误、没有 provider 请求，没有点击工作台 Apply 或 unknown-gate 确认。它增加原生交互证据，但不代表全矩阵或产品验收通过。

打包后的实际 executable 亦已通过隔离冷启动，见 [packaged-electron-smoke.json](evidence/agent-r4/2026-10-18/packaged-electron-smoke.json)：从 `app.asar` 加载 renderer，preload 与独立 profile 中的 SQLite 可用，合成方案/作品/源图/仅讨论参考可见，暂停项和 unknown 记录保留，renderer 错误为 0。没有点击收费确认，没有发起真实 provider 请求；进程已按本次 PID 与可执行路径精确停止。

## 独立数据与 Worker 风险复核

- **事务边界由真实 statement 注入验证。** `AgentSqlStore.transaction` 将 workspace、R4 JSON、submission 索引和 output slots 放进同一 SQLite 事务；coordinator 把 preparation 消费、approval receipt、execution 快照及 submit operation receipt 写入单个状态行提交；Worker 的 `onTransaction` 把 artwork、workspace message/attachment 与点评入队原子登记。`r4-atomic-enqueue.test.ts` 对 row UPDATE、submission-key INSERT、第二个 output-slot INSERT 三个真实顺序点逐一 rollback。`r4-execution-worker.test.ts` 在作品登记真实 workspace row 更新处故障，证明已完成 output/hash/本地路径先保存在 execution，关库重开后 `recover()` 可补登记且不重新提交；同 lineage 的另一 execution 被独立 `registration:<executionId>` gate 拦住，登记成功只释放此 gate，队列仍需显式 resume。`r4-critique.test.ts` 另以真实 SQLite trigger 失败点评交付事务，证明 review message 和 delivered receipt/messageId 均未提交、unknown 状态保留且恢复不重放已付费调用。另以真实 SQLite 丢失本地产物文件，验证恢复写入可修复失败事件/gate，不修改 completed provider 事实，也不阻断其他聊天的恢复读取。不能把这些 SQLite 事务结果外推为文件系统断电保证。
- **恢复采用 fail-closed，不自动重发越界请求。** Worker 对 durable queued 重启置 user_pause；有 boundary 的未核实请求转 unknown/gate；唯一可续跑的已确认逐图部分完成分支要用户显式 resume。`r4-recovery-matrix.test.ts` 将 queued、dispatching/no-boundary、发送前 cancel、running/pending、cancel_requested/pending、部分确认 slot、unknown 和 completed 做了五操作实际 SQLite close/reopen 矩阵。T11/T12 的共享 worker fake-provider 顺序与取消回执分支现有测试；仍未对每个真实 Host 入口分别跑同一并发故障矩阵，且 fake cancel contract 不能证明真实 native 服务支持或遵循取消语义。
- **需要维持的防线。** `hasActiveRequests()` 把 scheduled/pumping/controller 活动暴露给 portable busy guard；worker POST 前重新校验 cancel/gate/预算并先持久 boundary；未提供可靠远端取消的 provider 保持接收迟到结果；未知状态只允许查询/用户显式释放无关队列，禁止原 execution 重发。原生 smoke 已展示 B 恢复确认规则：操作者需选择并确认精确的独立新消息；旧 unknown 不重发、不删除，新 unknown 仍封锁后续收费动作。原生用例未点确认；后台确认后的持久写入、6 次合成模型回合和 2 个 fake 图片请求已由 T16 的实际 Pi/SQL/Worker 用例验证，不代表真实供应商请求。
- **崩溃状态一致性边界。** 正常流程中所有 outputs 完成时 `applyProviderResult` 已把 execution 提交为终态，因此持久化的 active+all-completed 组合应不可达；store 完整语义守卫会拒绝不合法行。`recover()` 对这种假想行当前会保守收敛为 unknown。建议保留一个针对损坏/不变量违例的 fail-closed 测试，避免把它误报为正常恢复。
- **导入与旧预设风险。** 旧归档缺 R4 文件的真实 SQL round-trip 已在 `data-backup-bridge.test.ts` 覆盖 per-chat preset binding 和冲突 ID remap；未知 preset 保留并阻断发送/准备，避免静默改用默认。该用例不替代不同数据库版本、损坏归档和用户真实数据恢复验收。
- **原生与服务范围仍单列。** 2026-10-18 原生 smoke 已完成并归档到 [evidence/agent-r4/2026-10-18](evidence/agent-r4/2026-10-18)：实际 Windows Electron main/preload/renderer 与 IPC 在隔离 `.tmp` profile 中运行，截图覆盖 800/1280/1920 viewport、viewer、队列恢复、workbench preview 和 unknown gate 文案。它使用合成 profile/作品，不证明真实用户迁移、真实账号/收费服务、远端取消能力、物理显示器/DPI或完整 T/U 矩阵。确认 Apply 和 unknown-gate B 的按钮未点击；两跳过测试也未纳入通过数。
