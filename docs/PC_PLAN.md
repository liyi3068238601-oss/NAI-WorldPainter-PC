# 绘世 PC 端规划

日期：2026-10-11。版本：0.3。状态：参考 UI 实机调查完成，执行路线与界面方向已定，应用开发未开始。

## 交付目标

**先把手机端现有全部功能完整移植到 PC，再增加其他功能。** 这是用户确定的最低标准。此前 0.1 中将漫画、Pixiv、长期记忆、多模态、分块重绘、Director Tools 和本地超分放到后续的安排已撤销。

PC 产品工作位于 `E:\NAI-WorldPainter\PC端`；GitHub 为私有仓库 `liyi3068238601-oss/NAI-WorldPainter-PC`。用户另行指定参考克隆到 `E:\NAI-WorldPainter\novelai_local_web`。首个目标平台为 Windows x64，最低系统版本在桌面与原生依赖验证后确定。

手机端功能依据本地当前工作区，而非只依据 README 或旧提交。基线为 HEAD 加当前源码状态，文件哈希见 [功能对照](MOBILE_PARITY.md) 的证据索引。对当前未提交 UI 改动只读调查；不把它们误标为上游已发布内容。

## 全量移植的含义

- 保留现有功能的用户可见能力、参数、渠道、工具、素材管理与数据工作流。NovelAI 官方和现有网关全部进入范围；已有 GPT、Nano Banana 等生图能力也不得遗漏。
- 每项功能必须有 PC 入口、可用实现、错误处理、必要的持久化与验收证据。只有按钮、占位页面、接口桩或隐藏的库代码不能算完成。
- Android 专用机制改成 PC 等价行为，例如相册保存变为文件另存，前台保活变为桌面任务生命周期管理，JNI 超分变为 Windows 后端；业务能力不因此取消。
- 已知缺陷不要求照搬。串图、丢参数、错误凭据复用和不可靠的结果保存应在移植时修正，不能用“行为一致”保留数据损坏风险。
- 未接线、占位或不可达代码与真正可用功能分开记录；任何范围不确定项先追踪调用链，不能静默删项。新增发现持续补入矩阵。
- 外部服务暂不可用时记为阻塞或未验证，保留范围；不能以一次失败为理由宣布该功能无需移植。

## 布局参考与绘世风格

用户指定 [NovelAI Local Web](https://github.com/YILING0013/novelai_local_web) 为 PC **界面、布局、动画与流畅感**的第一参考，[浪白 NovelAI Studio](https://github.com/2786886095/novelai-image-desktop) 为第二参考。默认布局优先研究前者：左侧导航，中部图库/画布与结果，右侧提示词/参数及底部生成区；浪白补充任务分区与桌面窗口行为。参考职责集中在交互体验，不以其功能清单替换手机端基线，也不由此指定后端架构。

用户同时明确：**两者都可以作为功能实现代码参考**。每项移植先调查已有模块和测试，再决定复用、组合、局部适配或独立实现。代码借鉴不限于界面；渠道协议、图片工具、数据存储、助手和漫画均可按需调查。参考项目独有的新功能放到 M7，不能挤占手机功能对齐。

绘世保留默认深色暖金主视觉：近黑背景 `#0A0A0C`、面板 `#1C1C21`、主色 `#F5D57A`，浅色模式沿用手机端白底蓝色体系。圆角、文字层级、按钮、图标和选中状态统一使用绘世主题，不复制参考项目的紫色渐变、品牌或宣传素材。具体来源和界面约束见 [设计方向](DESIGN_DIRECTION.md)。

桌面布局重排是移植的一部分，不必机械复制手机导航。功能入口不得因重排消失；拥挤窗口通过收起面板和“更多”入口保留全部功能。先验证 1280×720、1920×1080 与 100%/150%/200% 缩放；截图、交互和业务能力分别验收。动画与流畅感通过实际运行的页面切换、面板收展、图库滚动、缩放和长任务中的输入响应比较，不凭静态截图或动画参数判定。

## 技术路线

全量对齐优先于框架偏好。完成 [NovelAI Local Web 实机体验](REFERENCE_UI_REVIEW.md) 后，当前执行路线选定 **Flutter Windows 复用现有 Dart 业务，重做桌面表现层**。Electron + React + TypeScript 保留为关键用例失败且适配成本不可接受时的后备；浪白的成熟实现可减少部分重写成本，但不能代替手机功能逐项对齐。M1 先做 Flutter 原型和平台探针，不同时维护两套完整产品。

框架选择同时覆盖数据库、图片/蒙版处理、Agent、漫画、渠道协议、凭据和本地超分，不可只比较空窗口或外观。许可记录与平台插件的实际验证一并进行；许可未清楚的代码不能直接复制，但不能因此删掉对应功能。[技术路线](ARCHITECTURE.md) 记录待验证项。

## 数据与任务原则

草稿具备 ID/revision，提交时冻结任务与输入资产；异步生成和助手返回只能修改对应对象。保存用户输入与实际生效参数，单图记录真实 Seed，缺失值标未知。结果使用独立资产身份、SHA-256 与父图关系，另存派生图并保留原件。

图库索引与文件保存要能处理部分失败。图片成功落盘而索引写入失败时保留恢复记录。原有保存/删除/导入能力必须实现；必要的防丢失修复可以随移植完成，不受“新增功能后置”限制。

开发数据只进入本仓库被忽略的目录；用户图片、凭据与真实聊天不进入 Git。正式应用数据目录独立于程序安装目录，兼容中文、空格和无写权限路径。实际付费请求需明确账号与预算；不自动重试收费结果未知的请求。

## 验收规则

1. 矩阵中每项记录源功能、PC 入口、实现位置、自动化/人工/真实服务证据和状态，禁止只写“完成”。
2. 页面、设置、Agent 工具、后台能力与原生通道分别核对；不能只数页面。
3. 测试 401/429/超时/断网、磁盘满、缺失文件、重启恢复、中文路径，以及生成中切换草稿和渠道。
4. 随机 Seed 不伪造；收费结果未知不自动重发；源图 A 的操作不得处理 B。
5. 对比手机端源功能和 PC 输出；图片质量、蒙版合成、漫画对白布局、本地超分输出须有实际画面验证。
6. 自动化、真实接口与人工视觉证据分别报告；仅有模拟测试时保留“真实服务待验证”。
7. 原功能变化导致的差异必须列出原因与用户影响。功能缺失未经用户改变范围不能从矩阵删除，也不能算通过。

当前已实现绘世 PC 三栏工作台、主题、交互与 SQLite 自动保存，参考应用通过模拟上游完成体验。真实账号登录、付费生成、模型下载及完整手机业务移植尚未开始。下一批工作见 [迁移顺序](MOBILE_MIGRATION_NEXT.md)，功能范围继续以全部手机端能力为基线。
