# 界面与交互规范 · v3.2 R4 Final

这是目标 UI 规范；实际原型覆盖范围与结果见 [VERIFICATION.md](VERIFICATION.md)。沿用近黑暖金、浅色白蓝、摘要方案卡和图片优先，不另换布局体系。

## 页面与信息密度

左栏只管理聊天；顶部选择当前创作，旁边“全部对话 / 当前创作”控制阅读范围。进入聊天默认全部对话，消息标注归属。筛选不改当前创作和草稿；旧卡操作仍按卡片来源执行。“继续修改”则显式切到原作品创作，保存离开处草稿。

右栏固定为**当前方案 → 选中作品 → 创作要求 → 折叠详情**。“后续讨论基线”统一改成“当前方案”。这个名字仍表示讨论基准，与工作台和生成任务相互独立。

方案默认只露标题、修订、一句变化和少量关键词；“用此版本生成”为主动作，“设为当前方案”为次动作，工作台应用在更多菜单。不在每张卡出现“全文默认收起”；显示偏好只在一个菜单设置。完整词按需展开。实际差异与摘要分别有来源，摘要不能替代保存字段。

模型与助手预设在输入框下方同一紧凑工具栏。助手预设显示已选项和独立启用开关；关闭只跳过该预设正文并保留选中项，基础规则仍生效。预设面板提供“设为新会话默认”，默认值同时保存选中项与启用状态。每条消息的模型、预设版本等收入“详情”，正文不常驻技术元信息；切换时仅轻提示一次“之后发送生效，已排队保持原版本”。任务必要状态、归属和原型标记仍可见。

## 图片输入：显示、状态与执行一致

| 用户动作 | 立即可见变化 | 状态与后续执行 |
| --- | --- | --- |
| 点改图源胶囊 × | 源图胶囊消失、右栏无改图源、未提交预览失效/刷新 | 清除 edit source 与依赖蒙版/待发源绑定，增加 inputRevision；原作品仍在 |
| 在聊天明确说移除改图源 | 同步上述变化，有可撤销回执 | patch_creation_inputs，与 × 共用应用命令；歧义才询问 |
| 选“仅讨论” | 生成参与取消勾选并禁用；胶囊显示“仅讨论” | includeInGeneration=false；host 对矛盾 payload 拒绝 |
| 选色彩/构图/角色等有效用途 | 胶囊显示用途；参与生成独立勾选 | 切用途本身不自动授权；用途或 role 改变默认不参与；仅同目标、同附件/修订、同 role、同 `referencePurpose` 且未撤销的授权可保留；能力不支持时说明 |
| 明确勾选参与生成，或在聊天明确要求确切图片参与本次生成 | 只更新指定绑定的参与状态并显示回执 | host 将原用户事件、同一 userIntentRef、确切目标、附件/修订、role、`referencePurpose` 与授权范围记录为证据；模型传 `includeInGeneration=true` 本身不是证据 |
| 在聊天明确改参考用途 | 更新胶囊/右栏/未提交预览并有回执 | 精确附件与 expectedInputRevision；只有明确 opt-in 才可参与生成；不修改已发送内容 |
| 撤销输入修改 | 成功则恢复原绑定 | 只有当前 inputRevision 仍匹配该回执且附件有效才可恢复；否则提示冲突 |
| 查看已经提交的任务 | 展示“已提交输入” | 保留旧快照；清胶囊不会取消或改写该任务 |
| 普通聊天、生成入队或生成完成 | 原改图源胶囊及右栏来源保持不变；新结果作为独立作品加入 | 这些事件不清除或替换 edit source；仅明确移除、选取新改图源或“继续修改”明确绑定某结果时才改变来源 |

胶囊的 × 只移除该用途，不删除图片资产。若同一作品同时为改图源与独立参考，分别显示两个有明确用途的入口；取消改图源不暗中删除参考。改图源持续绑定，直到用户明确移除或换图；普通聊天及生成入队/完成均不清源或把新结果自动设为源。“继续修改”只在明确选择作品后将该作品设为新改图源。普通选择源图以胶囊与右栏变化反馈，不弹长说明。

导入、查看器、右栏、聊天工具和生成快照共用同一用途枚举与约束。界面统一写“参与生成”，技术详情才使用 includeInGeneration 等字段。UI 禁用只是第一层；执行前仍验证归属、修订、inputRevision 和服务能力。不通过静默删除非法参数“修复”用户请求。

同步用途修改和异步聊天/图片回执更新后，均按稳定 sectionId 与 bindingId 保留当前 details 展开态、滚动位置与控件焦点，便于继续勾选。只有更新前焦点确实在被替换区域内才恢复；焦点在 composer 时不得拉回。旧控件因新用途变为禁用时，落到同绑定有效控件或区块标题；切换创作时不把前一创作的焦点强套到后一创作。参考入口打开查看器时保留 binding 上下文；即使 attachmentId 同时出现在作品库，也显示本创作真实参考用途。撤销冲突须留在原回执旁，明确未恢复；短通知只能辅助，不能取代持久状态。

## 输入与文字队列

Enter 发送后清空，Shift+Enter 换行；输入法候选态 Enter 不发送。输入区随内容增长，有最大高度，附件只在存在时占空间。

新消息默认排队，可取消并恢复草稿；取消按确切 messageId 与 composer draftRevision 做 CAS，只在 composer 仍处于发送清空后的版本时恢复原正文/附件/配置。若用户已写入新草稿，保留新内容，并把取消消息留在独立的可恢复入口，不能覆盖新草稿。同一创作的活动回复可接收“立即引导”。登记后显示“等待引导生效”，到安全节点可靠接收才标明生效。若回复先正常结束，引导转成下一条消息一次处理；停止或错误时未消费消息保留并暂停。每会话同时一个模型回合；图像队列不因文字停止而取消。输入下一条尚未发送的聊天草稿只更新文字草稿，不改变图片输入修订，也不使已发明确用途修改或固定提案预览误报冲突；真正的参考/源图/生成参数修改仍须触发 CAS 与预览失效。

## 窄窗和短通知

800px 示例只保留**顶栏左侧“聊天”、右侧“当前创作”各一个抽屉入口**，不在对话标题重复一组。位置随窗口保持稳定；按钮有明确可访问名称。打开抽屉时管理背景 inert、焦点循环和 Escape；继续修改先关闭抽屉、解除 inert，再聚焦输入。

短通知放在输入框上方，不覆盖文本框、工具栏或发送按钮；输入因附件或换行增高时位置同步。正常可见的选择变化不重复发 toast。错误、撤销冲突等短通知可以显示，持久失败仍留在相应卡片，不能只靠会消失的 toast。

## 大图查看器

聊天作品保持完整大图，操作紧随图片；右栏采用精简选图。点击图片与“查看”进入同一个 viewer，初始适应窗口，图像保持完整纵横比；缩放后允许滚动或平移，不裁掉原图来填满容器。

| 控件 | 语义 |
| --- | --- |
| 适应窗口 | 按可用空间显示完整图，并显示缩放状态 |
| 放大/缩小 | 只改变显示比例；切图后恢复适应，避免继承上一图的错误定位 |
| 上一张/下一张 | 默认同一生成批次，按 outputIndex；头尾禁用并提示当前位置 |
| 范围切换 | 本批次 / 当前创作全部作品；基于来源 creation，不混入别处 |
| 下载原图 | 当前附件原字节及正确扩展名；无法读取时明确失败 |
| 实际种子 | 当前附件对应回执/可信元数据中的 resolvedSeed；同时显示来源，未知时标未返回 |
| 继续修改 | 明确绑定当前查看的那张作品并显式设为新改图源；不因翻图自动改变源图 |
| 作为参考 | 先选用途，默认仅讨论；参与生成显式勾选 |

图片切换不会改变当前方案、工作台、生成快照或改图源。新产物加入集合时保持当前 attachmentId，不因数组插入跳到别图，也不自动替换 edit source。只有一张时禁用前后，空集合提供关闭入口。横、竖、不同分辨率、缺 seed、多图和第二张派生结果分别验证。

图片 role=button 支持 Enter/Space；查看器关闭恢复实际触发控件，范围 select 不按 data-action 按钮查找。翻到首尾后原前后按钮若变为 disabled，焦点转到可用导航按钮，其次范围 select，最后当前图标题，不落到失效按钮或 body。导入图使用解码后的 naturalWidth/naturalHeight，不按示例 fixture 名称猜横竖；按 outputIndex 排序后仍保持当前 attachmentId。

原型下载按钮明确写“下载示例 SVG”；真实文件导入如可读则下载原文件。示例 seed 标为模拟，不能展示为真实服务 seed。大图前后对比后做，本轮不扩展。

对话框行为参考 [W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)；下载依赖浏览器同源/blob URL 等限制，不能把远端 URL 可展示等同于可下载，参考 [MDN download 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a#download)。产品使用 host 文件能力时也要校验当前附件，不靠截图代替原图。

## 生成与恢复

预览首屏显示“生成到”、新图/改图、来源修订、实际源图/参考、模型、尺寸、数量、费用和阻断原因，完整词可折叠。确认仅提交同一 fingerprint，一次用户意图双击不创建两个任务。

预览打开时绑定目标、inputRevision 与 fingerprint。聊天同轮 `patch→prepare` 使用原用户消息发送时冻结的 model 与助手预设配置（含 preset ID、revision、正文 hash 和 enabled）；之后切换当前聊天配置既不倒灌该操作，也不使这份固定配置自动失效。直接从方案卡发起的生成则在打开预览时固定当时配置。固定配置的 provider/账号/能力若实际不可用，阻断并说明，不静默替换。`currentPlanRef` 只作讨论溯源，不进入显式旧版方案或工作台输入的生成 fingerprint。随后聊天工具或界面修改相关图片输入，旧预览立即标“输入已变化”，确认不可用，提供重新预览；确认入队时还须原子复查目标、inputRevision 与 fingerprint，不能只靠按钮 disabled。重新预览刷新图片输入，但保留用户指定的确切提示词方案修订；原版本无效时明确阻断，不自动选最高修订。仍要求重新确认。持久入队前的依赖 seed 变化也使旧批准失效，provider 请求为 0；持久入队后改 seed 才不影响原任务。无关创作的输入不误使该预览失效。已入队任务卡显示原快照，不随编辑刷新。

全局队列与聊天任务卡引用同一执行记录。入队不等于成功，查询完成不等于生成完成；取消已经完成的任务显示“已完成，未取消”。部分图片立即可见，批次点评通过同会话队列安排一次。

重启后，确定尚未发送的已确认任务默认暂停，显示“继续队列”。恢复时校验原输入和批准，不重算最新默认值。可能已发送的任务先核实，绝不自动重发。核实失败后后续仍暂停，需逐项明确恢复独立任务；恢复时附件无法读取则阻断旧快照，要求重选附件并新建预览。

取消未发送任务成功后不再领取，显示“已取消，未发送”。已领取但尚无发送证据时，显示“已请求取消，正在确认是否已发送”；持久取消意图独立于 dispatching，不伪造在途项。确认发送前已停止才显示“已取消，未发送”，发送不明显示待核实。运行中只显示“已请求取消”，收到终态后再显示确认取消；服务不支持取消时明确标明并继续接收结果。回执不明显示待核实，迟到成功仍展示图片，已完成任务保留结果并提示“已完成，未取消”。全局队列与聊天任务卡引用同一个执行记录；停止文字回复单独处理。

独立 HTML 的演示菜单提供恢复、取消及聊天修改用途场景。演示暂停由具体演示任务持有：取消一项只释放该项原因，最后一个持有者解除后重新调度；failure/unknown/cancel_requested 等独立护栏不因此解除。队列中仍有在途项时，未来派发阻断只显示为暂停原因，不伪装整单终态。演示计数仅记录本地模拟事件；sessionStorage 重载演示也不代表真实应用持久队列、远端取消或扣费已验证。具体入口和实测路径见 README、VERIFICATION。
