# R4 Final 实施前复审

日期：2026-10-18。范围仅为综合设计、工具合同、基础提示词与独立 HTML。原 R4 目录/ZIP 保留；本轮没有修改实际产品代码。用户报告与反例作为审查材料，其中的实施建议不构成执行授权。

## 审查结论的含义

这一版是进入实施的设计基线。它定义要实现的行为，不能证明这些行为已经存在于 Electron/Pi 产品中。静态合同检查、浏览器演示与真实 host/provider 验收分开记录；本轮实测以 [VERIFICATION.md](VERIFICATION.md) 为准。

## 本轮修订

| 问题 | 收敛规则 |
| --- | --- |
| 普通聊天发送会清空改图源，连续发送还会导致前一条清源指令假冲突 | D20：源图保留到明确移除/换图。普通聊天、入队、完成不清源；生成结果不自动成为新源；预览始终标源 |
| 纯文本草稿恢复/演示填入改变图片修订；恢复旧消息可能覆盖新草稿 | 文字与图片修订分开；恢复有冲突时保留两份，只有实际图片输入变化才更新图片修订 |
| 操作类消息被合并为文字引导后没有执行却显示完成 | 本原型只将普通文字合并为引导；精确操作指令保留独立队列并说明原型范围。产品仍按同回合授权、目标与安全节点处理引导，不能静默丢操作 |
| 同轮修改参考后生成可能读到后来切换的配置 | 使用发送时固定的 conversationConfig；直接卡片操作在预览时固定；自动点评继承执行配置，不读取运行时当前选择 |
| 固定提案预览因切换讨论中的当前方案而失效 | 当前方案只作讨论来源；显式提案/工作台输入不受该指针变化影响，真实输入变化仍校验 |
| 文档存在关闭预设，但 UI 无入口，旧字段语义易被混用 | 当前会话显式启停，关闭保留选择，只停用附加正文；独立保存新会话默认；版本化新绑定，不重命名旧字段 |
| 已失败/取消输出仍可进入下一 dispatching | 领取前必须全部为 completed/not_dispatched；失败停发，取消不续跑；保留已经返回的产物 |
| 非终态中的 failed 项不要求错误码；成功结果可声明无 provider 回执 | 所有阶段 failed 都需有效错误码；实际服务输出需已确认回执，not_applicable 限确未请求的阶段 |
| cancel_execution 可把本地 queued/领取中 dispatching 报为服务不支持取消 | 本地 CAS 或持久取消意图；服务 not_cancellable 仅适用于已有在途/未知执行证据的状态 |
| 模型可写 includeInGeneration=true，但授权来源不明确 | 明确 UI 勾选或同意图、确切参考的聊天参与授权；角色修改本身不授权；模型字段不构成授权证据 |
| 排队取消主卡没有明确区分未发送；下载通过临时隐藏元素触发 | 只有提交前取消的确切证据才显示“已取消 · 未发送”；下载采用可见原生文件链接，示例 SVG 和导入原图分开 |

唯一新增的用户决策为 **D20 源图持续保留**，已经确认。其余修订落实既有规则或补齐证据要求，没有另选视觉方向，也没有扩展生图供应商。

## 进入实施的首个切片

先在真实 host 与持久测试 store 中贯通：读取创作 → 提案/同轮参考修改 → 准备真实生效输入 → 批准并原子入队 → worker → 登记可读附件 → 查询与展示。使用 fake provider 记录实际请求次数和 payload，覆盖取消竞争、失败/unknown、崩溃恢复、重复提交和第二张派生编辑；再按同一契约扩展五类图像入口。

实现完成后必须分别取得真实 host + fake provider、真实模型协议、真实图像服务、Windows 原生 UI 与迁移读回证据。这里列出的是实施验收顺序，不是新一轮设计待决项，也不是本轮已经执行的测试。

## 本轮验证限制

下载链接的 SVG 内容已读取并验证，文件名与类型正确；内置浏览器的 download 事件/保存 API 均未返回落盘回执，因此没有把“点击下载”或提取链接内容写成实际下载成功。外部浏览器保存、导入原图逐字节下载与真实服务附件仍需实施验收。HTML 的固定指令、预写点评和 sessionStorage 恢复只证明演示路径；它没有通用语言理解、真实服务能力漂移或产品磁盘事务。
