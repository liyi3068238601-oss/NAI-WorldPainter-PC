# 需确认的行为边界与可复跑测试设计

以下是源码影响分析与测试设计；除第一阶段已记录的默认勾选和局部回填外，不能把未执行矩阵标为通过。本阶段不修改这些业务语义。

## U02：元数据回填是否默认清空参考图

`MetadataApplyPanel.tsx` 默认选全部；`metadata-selection.ts` 为 NovelAI 报告附加角色、参考图和模型模式，即使源图没有可用角色或参考文件。`png-meta.ts` 为原图重现语义补空画风、质量/负面预设等字段；`store.ts` 合并后立即持久化。

默认应用可能清空 Vibe 与精准参考、替换或清空角色、覆盖画师串与预设。匹配已保存画师串前缀时还有拆回画风的恢复路径。它不删除图库/素材文件。正负提示词已有局部文本撤销，不等于整套参数、角色、参考图的事务撤销。现有 `metadata-selection.test.ts` 把“全选清空、未选保留”写成既有预期，不能只改勾选而忽略复现语义。

建议用户先选择：

| 方案 | 行为与代价 |
|---|---|
| 默认保留当前参考图/角色，明确勾选才替换或清空 | 降低误清空；回填后未必完整重现原图，需要清楚显示保留项。建议优先评审此方案。 |
| 默认还原原图状态，保留当前全部勾选语义 | 利于复现；必须在应用前明确展示将清空的数量，并提供整套回滚。实施范围较大。 |

测试夹具：独立 profile；合成 Vibe 2 张、精准参考 1 张、角色 2 个，分别设置独特正负词、画师串、Seed、质量预设。每步比较预览、应用结果、持久化结果与重启结果，不读取真实素材。

待跑矩阵：全选；仅正向；仅 Seed（含 0）；不勾参考图；源图无角色；源图有多角色；参考文件缺失；空负向；空画风；已保存画师串前缀；取消应用；应用后文本撤销与整体撤销差别；重启。验收须明确“保留、替换、清空”各自的提示和数量，以及失败时是否留下半更新状态。

## U03：Agent 草稿跨页、预填与冷启动

`PiAgentPage.tsx` 文本与动作草稿按 chat ID 保存在内存和 sessionStorage；附件另在 Agent workspace 中持久化。切页/切聊天通常保留；完整退出后的文本恢复没有同等保证，第一阶段实际验证文字丢失而附件保留。

源码还显示：编辑旧请求、重试、修改方案、继续编辑和空会话快捷入口会直接预填，可能覆盖已输入的下一条。参考图快捷入口先预填再打开选择器，取消选择器仍可能留下覆盖。另有待实测异步风险：发送后输入 NEXT_B，若 IPC 在记录用户消息前失败，恢复旧 input 可能覆盖 NEXT_B。它们不是同一个“自动保存”问题。

建议分别确认：

- 冷启动：是否按会话持久化“文字+待执行动作+附件引用”这一完整草稿，并增加恢复时间提示；清除、归档、删除、备份和迁移如何处理。
- 非空预填：采用追加、替换前确认，还是保留当前默认覆盖。建议非空草稿先提供明确选择，空草稿保持快速入口。
- 失败恢复：建议只在输入版本未改变时原位恢复；用户已经继续输入时，将失败输入作为可恢复项，避免覆盖新内容。

待跑矩阵：每个预填入口×空/非空草稿；选择文件取消；待确认时写下一条；请求延迟后失败；失败前/后是否已记录用户消息；A/B 两会话往返；切页面；正常关闭和强制退出；附件缺失；归档/删除与恢复。固定使用 `OLD_A`、`NEXT_B` 等合成标记。验收观察文字、动作、附件、时间戳与持久化文件，而不是只检查聊天列表。

本阶段仅原型展示当前打开期间的内存草稿保留，不承诺上述产品行为已实现。需用户确认后再修改业务逻辑与既有测试。
