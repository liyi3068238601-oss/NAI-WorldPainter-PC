## 布局如何落到绘世

| 参考行为 | 绘世采用方式 | 验收场景 |
| --- | --- | --- |
| 首要参考的左导航、大画面与右参数 | 左侧导航；中部图库/画布及结果；右侧提示词、角色、参考和参数 | 收起导航不丢当前位置，画面仍是视觉中心 |
| 首要参考的底部生成与额度区域 | 主要生成操作保持可见，展示当前渠道、批量状态、费用来源 | 参数再长也不挤走生成键，不遮挡错误 |
| 首要参考的参考图库与本地图库入口 | 区分参考材料与生成结果，用一致的详情和图像动作 | 对图片 A 的操作不能作用于 B |
| 首要参考的提示词与参数分组 | 保留手机所有字段，常用项可见，高级项折叠且可搜索定位 | 改渠道前列出不兼容字段，不静默清空 |
| 浪白的任务导航和宽工作区 | 助手、漫画、素材与 Pixiv 按任务切换，保留独立状态 | 从任务返回后草稿、选中图片和队列不丢 |
| 浪白的窗口工具与导航溢出 | 参考输出目录、窗口操作和“更多”入口的组织方式 | 窄窗口和高 DPI 不隐藏功能 |

原型优先使用首要参考的列顺序；浪白的左编辑、右历史是对照方案。布局重排属于 PC 移植，不能由此引入尚无需求的多套布局系统。

## 动画与流畅感

首要参考的源码可定位到以下行为。侧栏、主题、图片缩放、参数折叠已在本机运行操作；提示词联想完整键盘流程与系统减少动画偏好尚未验收：

| 源码（相对首要参考根目录） | 已发现的实现 | 绘世要借鉴的体验 |
| --- | --- | --- |
| `next_nai_web/src/app/main/page.js` | 侧栏宽度/背景过渡、导航悬停与动画开关/速度 | 侧栏和工作区切换连续，定位稳定 |
| `next_nai_web/src/providers/AppThemeProvider.js` | 随动画设置变化的背景、边框、文字颜色过渡 | 主题切换不闪白，动画时序统一 |
| `next_nai_web/src/components/ai-painting/ItemDisplay.js` | 图片卡片 transform/opacity 与悬停操作过渡 | 操作反馈清晰，卡片不跳动 |
| `next_nai_web/src/components/ai-painting/ItemPreview.js` | 大图预览控件的短过渡 | 缩放、切图、打开/关闭预览自然且可打断 |
| `next_nai_web/src/components/ai-painting/PromptEditor/usePromptSuggestions.js` | requestAnimationFrame 调整提示词建议定位 | 输入、光标和联想列表跟随稳定 |
| `next_nai_web/src/components/ai-painting/PromptEditor/EnhancedPreview.js` | 局部遵循 prefers-reduced-motion | 减少动画时仍能看懂状态变化 |

这些实现不能证明整个应用没有卡顿。本轮已操作参考的工作区切换、侧栏、图库滚动、图片缩放、提示词编辑和蒙版绘制，保存截图与侧栏采样帧。拖入文件、大图压力、长任务中连续编辑与系统高 DPI 仍需测试；M1 必须用相同操作验证绘世原型。

绘世的实现原则：不让动画阻塞点击；新动作能中断旧过渡；滚动与输入不等待网络；缩略图加载不造成大面积布局跳动；耗时解码/处理不阻塞界面；减少动画时保留状态反馈。具体时长与缓动在原型中对比定案，不把复制时长参数当成复制流畅感。

M1 在记录硬件、窗口和样本规模后，保存交互录屏与帧时间/输入响应测量。长任务、较大图库和高 DPI 分别验证；结果未经测量不写“丝滑”“稳定 60 FPS”等结论。本轮参考体验为 36/37 张几何测试图和一次模拟生成；10 张动画采样帧不是连续录屏或性能基准。

## 实机体验后的原型规格

当前确定三栏列顺序和固定生成区。1440px 原型基准：导航展开约 208px、折叠 64px，右侧参数约 400px，中央弹性填满；低于 1360px 默认折叠导航。顶部任务标签保留草稿，中央底部仅放当前结果，完整图库单独打开。长参数面板提供分组定位，提示词可展开为大编辑器，角色卡支持保留内容的临时禁用。

动作与源图绑定，图片详情提供全部/仅提示词/选定字段回填。生成任务从草稿冻结，用户继续编辑不改变已提交请求。未知进度使用阶段与耗时显示，费用显示渠道和估算来源。动效初值为悬停/按下 100–140ms、展开/折叠 180–220ms、主题 180ms，允许中断；减少动画时取消位移和缩放。当前原型已实现全部/仅提示词回填、冻结模拟任务、200ms 导航收展和180ms主题过渡；选定字段回填、费用与真实任务尚未实现。

## 绘世自己的主色与组件风格

下面是手机当前主题代码的提取值，不是参考项目取色。

| 语义 | 默认深色 | 现有浅色 |
| --- | --- | --- |
| 背景 | `#0A0A0C` | `#F2F4F8` |
| 面板 | `#1C1C21` | `#FFFFFF` |
| 主色 | `#F5D57A` 暖金 | `#3B82F6` 蓝 |
| 主色上的文字 | 黑 | 白 |
| 正文 | 白 | `#172033` |
| 次级正文 | 白色 60% | `#5D6B82` |
| 辅助色 | `#6C5CE7` | `#8B5CF6` |
| 第三色 | `#2DD4BF` | `#14B8A6` |

金色用于主要操作、焦点和选中状态，画面本身保持视觉中心。卡片基准圆角 16，输入/按钮基准 12；桌面可以提高信息密度，但保持绘世的克制层次、中文文字层级与轻边框。原型内置 OFL 许可的 Noto Sans SC 完整字体，不依赖在线字体服务，来源与哈希见 THIRD_PARTY.md。

不移入首要参考的品牌蓝灰或浪白的紫色渐变、玻璃光晕、标志与宣传角色。两种现有主题均需覆盖。`coffeePaper` 虽有枚举，但当前 `app.dart` 拒绝切换、主题页没有入口，属于预留代码，不能视为已完成第三套主题。

## 视觉验收边界

M1 制作可交互原型后，对照参考画面与绘世手机主题验证导航覆盖、画布比例、提示词可读性、按钮层级、收起面板、空态/失败态和生成状态。至少覆盖 1280×720、1920×1080 及 100%/150%/200% 缩放。

当前 Flutter 原型已在内置浏览器实际操作并保存 1280×720、1440×900、1920×1080 截图，见 PROTOTYPE_REVIEW.md。已修复侧栏底部主题按钮挤压、640×480 导航抽屉溢出和角色网格末行裁切。Windows 原生 DPI、帧时间、复杂图像压力与用户观感验收仍待完成；本轮结果不证明生产性能。
